# Cagnard v0.12.1

OIDC deployments with self-signed certificates now have an explicit TLS compatibility option, and authentication failures report their stage and cause in backend logs.

## Self-signed certificates

- **Recommended:** mount your CA certificate in the backend and set `SSL_CERT_DIR=/etc/ssl/certs:/etc/cagnard/ca`. TLS certificate and hostname verification stay enabled.
- **Explicit exception:** set `trustAllCertificates = true` inside the relevant `auth.providers` OIDC object. This disables certificate-chain and hostname verification for that provider's discovery, token exchange and signing-key requests. It defaults to false and emits a startup warning when enabled. HTTPS and OIDC protocol checks still run, but an impersonated IdP could capture credentials or supply false identities.

The [OIDC guide](https://github.com/k3rnL/cagnard/blob/v0.12.1/docs/guides/oidc.md#self-signed-certificates-and-private-cas) documents both methods with Helm and Compose examples. No new HOCON field is needed for the trusted-CA method.

## Authentication diagnostics

Failed starts and callbacks now include safe `failure.stage` and `failure.reason` fields, with an HTTP status where available. Diagnostics distinguish certificate trust, hostname, DNS, connectivity, timeout, issuer, transaction, token and session failures. Discovery backoff retains the original cause. Additional `oidc_http` records identify outbound request failures; static-login and origin-check failures also include reasons.

Logs exclude credentials, cookies, tokens, authorization codes, state/nonce values and raw upstream response bodies. Browser error messages remain generic. See the [diagnostic reference](https://github.com/k3rnL/cagnard/blob/v0.12.1/docs/guides/oidc.md#read-the-backend-diagnostics).

## Upgrade

Deploy matching frontend and backend `v0.12.1` images and Helm chart `0.12.1`. Existing v0.12.0 configurations remain valid; no auth schema migration is required. Restart the backend after changing configuration or mounted trust certificates. Changing `trustAllCertificates` invalidates that provider's pending logins and existing sessions.

An older frontend can navigate directly to the OIDC start endpoint and receive `invalid_session`; check explicit Helm image overrides and reload stale browser/proxy caches when upgrading. Before rolling back to v0.12.0, remove the new `trustAllCertificates` field, because its strict auth decoder does not recognize it.
